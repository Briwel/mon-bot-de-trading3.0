Explication du Bot de Trading

Ce document explique le fonctionnement du bot de trading conçu pour automatiser les transactions sur la paire BTC/USDT en se basant sur une stratégie d'analyse technique.

Stratégies de Trading

Le bot utilise une stratégie de "scalping" à court terme en se basant sur trois indicateurs techniques principaux : les Moyennes Mobiles (MA), l'Indice de Force Relative (RSI) et les Bandes de Bollinger.

Stratégie d'Achat

  • Croisement des Moyennes Mobiles (MA) : La moyenne mobile à court terme (MA courte, 20 périodes) doit être supérieure à la moyenne mobile à long terme (MA longue, 50 périodes).
  • Indice de Force Relative (RSI) : L'Indice de Force Relative (RSI, 14 périodes) doit être inférieur à 70.
  • Indicateur des Bandes de Bollinger : Le prix actuel doit être inférieur à la bande supérieure des Bandes de Bollinger.

Stratégie de Vente

  • Take Profit : Le prix actuel atteint un seuil de profit défini, déclenchant la prise de bénéfices.
  • Stop Loss : Le prix chute en dessous d'un seuil de perte prédéfini, ce qui permet de limiter les pertes.

Logique du Code

1. Structure

Le code est organisé en plusieurs fonctions pour une meilleure lisibilité :

  • load_config() : Charge les paramètres depuis le fichier de configuration.
  • load_state() : Charge l'état du bot depuis bot_state.json.
  • save_state() : Sauvegarde l'état actuel du bot.
  • fetch_data_and_indicators() : Récupère les données et calcule les indicateurs.
  • check_buy_signal() : Vérifie les conditions d'achat.
  • check_sell_signal() : Vérifie les conditions de vente.
  • execute_trade() : Exécute les ordres via l'API.
  • run_bot_logic() : Contient la logique principale.
  • main() : La fonction principale qui gère le traitement en parallèle.

2. Flux d'exécution

  1. Initialisation : Le bot charge la configuration et se connecte à l'API.
  2. Boucle de paires : Il parcourt chaque paire de trading définie.
  3. Récupération des données : Pour chaque paire, il récupère les données de marché les plus récentes.
  4. Analyse des signaux : Il vérifie les signaux d'achat et de vente.
  5. Mise à jour de l'état : L'état du bot est mis à jour après chaque transaction.
  6. Pause : Le bot se met en veille avant de répéter le processus.

Résilience et gestion d'erreurs

  • Variables d'environnement : Les clés API sont chargées depuis des variables d'environnement pour des raisons de sécurité.
  • Gestion des erreurs de l'API : Le bot incrémente un compteur en cas d'échec de l'API. S'il dépasse un seuil, le traitement de la paire est mis en pause sans arrêter le bot.
  • Gestion des transactions : Des vérifications sont effectuées avant chaque transaction pour s'assurer que les fonds sont suffisants.
