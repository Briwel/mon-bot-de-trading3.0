Explication du Bot de Trading

Ce document explique le fonctionnement du bot de trading conçu pour automatiser les transactions sur plusieurs paires (BTC/USDT, ETH/USDT…) en se basant sur une stratégie d'analyse technique combinant MA, RSI, Bandes de Bollinger et ATR.

Stratégies de Trading

Le bot utilise une stratégie de "scalping" à court terme en se basant sur trois indicateurs techniques principaux : les Moyennes Mobiles (MA), l'Indice de Force Relative (RSI) et les Bandes de Bollinger.

Stratégie d'Achat

  • Croisement des Moyennes Mobiles (MA) : La moyenne mobile à court terme (MA courte, 20 périodes) doit être supérieure à la moyenne mobile à long terme (MA longue, 50 périodes).
  • Indice de Force Relative (RSI) : L'Indice de Force Relative (RSI, 14 périodes) doit être inférieur à 70 (évite le surachat).
  • Bandes de Bollinger : Le prix actuel doit être inférieur à la bande supérieure.
  • Position sizing ATR : La taille de la position est calculée pour que la distance de stop-loss (ATR_MULTIPLIER × ATR) représente exactement 1 % du capital total, plafonnée à 10 % du capital.

Stratégie de Vente

  • Take Profit (+3 %) : Le prix atteint +3 % au-dessus du prix d'achat (+ frais de transaction) ; le bot vend pour encaisser le bénéfice.
  • Stop-loss suiveur (ATR) : Le stop est positionné à ATR_MULTIPLIER × ATR sous le plus haut atteint depuis l'achat. Il remonte automatiquement avec le prix (trailing stop dynamique basé sur la volatilité réelle).

Logique du Code

1. Structure

Le code est organisé en plusieurs fonctions pour une meilleure lisibilité :

  • load_state() : Charge l'état persisté depuis bot_state.json (positions, disjoncteur).
  • save_state() : Sauvegarde l'état actuel du bot.
  • check_circuit_breaker() : Vérifie si la perte 24 h dépasse le seuil ; suspend le trading si nécessaire.
  • get_ohlcv() : Récupère les données OHLCV depuis Binance (bougies fermées).
  • get_account_balance() : Récupère le solde du compte.
  • calculate_position_size_usdt() : Calcule la taille de position via l'ATR (risque constant de 1 %).
  • handle_buy_signal() : Exécute un ordre d'achat si les conditions sont réunies.
  • handle_sell_signal() : Exécute un ordre de vente (TP ou trailing stop ATR).
  • run_bot_logic() : Contient la logique principale par symbole (calcul des indicateurs + signaux).
  • main() : Boucle principale — connexion, disjoncteur, itération sur les paires, sauvegarde d'état.

2. Flux d'exécution

  1. Initialisation : Le bot charge l'état persisté et se connecte à l'API Binance.
  2. Récupération du solde : Le solde USDT est récupéré à chaque cycle.
  3. Vérification du disjoncteur : Si la perte 24 h ≥ 5 %, tous les trades sont suspendus jusqu'à la fin de la fenêtre.
  4. Boucle de paires : Pour chaque paire active (BTC/USDT, ETH/USDT…) :
  5. Récupération des données : Bougies OHLCV fermées récupérées depuis Binance.
  6. Calcul des indicateurs : MA20, MA50, RSI14, BB20, ATR14 via TA-Lib.
  7. Analyse des signaux : Vérification des conditions d'achat ou de déclenchement du TP/trailing stop.
  8. Sauvegarde de l'état : L'état complet (positions + disjoncteur) est écrit dans bot_state.json.
  9. Pause : Le bot attend 60 secondes avant de répéter le processus.

Résilience et gestion d'erreurs

  • Variables d'environnement : Les clés API sont chargées depuis des variables d'environnement (BINANCE_API_KEY, BINANCE_SECRET_KEY) pour des raisons de sécurité.
  • Disjoncteur de perte journalière : Si le capital USDT baisse de ≥ 5 % sur 24 h, le bot suspend automatiquement tous les nouveaux ordres jusqu'à la fin de la fenêtre courante. L'état est persisté dans bot_state.json pour survivre aux redémarrages.
  • Pause automatique par symbole : Après 5 échecs API consécutifs sur une paire, cette paire est mise en pause pendant 1 heure sans arrêter le reste du bot.
  • Gestion des transactions : Des vérifications sont effectuées avant chaque ordre (solde disponible, montant minimum min notional de l'échange).
  • Mode simulation (Paper Trading) : L'option PAPER_TRADING_MODE = True permet de simuler tous les trades sans aucun ordre réel.
  • Historique des trades : Chaque transaction est enregistrée dans trade_history.csv avec horodatage, symbole, type, prix, quantité, total et frais.
